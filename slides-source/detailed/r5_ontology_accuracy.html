DAY 1 · MD §D1.2.9.6 · ONTOLOGY ACCURACY

本体准确性：四条保证措施Ontology accuracy: four guarantees

本体不是建完就准。接入、准出、执行、回流四条措施持续保证准确性，每条都留下可复核的证据。An ontology is not accurate once it is built. Ingestion, exit tests, action execution and issue feedback keep it accurate, each leaving reviewable evidence.

01

高质量数据接入High-quality data ingestion数据DATA

优先接入可追溯、已授权、口径明确的数据；来源或口径暂不清晰的先标为待确认，补齐后再进本体；原始数据、AI 草稿与专家确认分层存放。Prefer traceable, authorised data with clear definitions; data whose source or meaning is still unclear is marked as pending and only enters the ontology once confirmed; raw data, AI drafts and expert-confirmed knowledge stay in separate layers.

02

测试用例的准出执行Test cases gate the exit准出EXIT TESTS

每次本体或规则变更都跑既定用例集，覆盖正常、缺失、冲突与异常样本；不通过不准出，差异、版本与回归记录留档；准出门槛在测试前与业务共同锁定，验收过程中不下调。Every ontology or rule change runs the fixed test set covering normal, missing, conflicting and exception samples; no pass, no release, with diffs, versions and regression records kept; thresholds are agreed with the business before testing and are not lowered during acceptance.

03

标准稳定 Action 的执行Standard, stable action execution执行ACTION

Action 走标准接口与受控权限，不绕过系统规则；执行前校验对象、状态与条件，执行后回写结果与回执；失败、越界或高风险动作转人工，并记录原因与处理人。Actions run through standard interfaces and scoped permissions, never around system rules; object, state and conditions are validated before execution and the result and receipt written back; failures, out-of-bound or high-risk actions go to people with the reason and owner recorded.

04

Agent 用 issue 驱动本体自迭代Agents raise issues, the ontology iterates回流FEEDBACK

真实任务遇到缺口、歧义或错误时，Agent 提 issue 而不是自行补造；issue 进本体评审，按影响范围分级，修复后回归，再以新版本发布并回流到用例集，形成闭环。When a real task hits a gap, ambiguity or error the agent raises an issue instead of inventing an answer; issues go to ontology review, are triaged by impact, regressed after the fix and released as a new version that feeds back into the test set.
