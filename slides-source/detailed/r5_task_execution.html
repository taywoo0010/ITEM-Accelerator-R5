DAY 1 · MD §D1.3.7 · KNOWLEDGE TO ONTOLOGY

Knowledge Fabric：把业务材料变成可执行知识Knowledge Fabric: from business evidence to usable knowledge

不只是把文档塞进检索库，而是形成可查询、可验证、可交付给 Agent 的业务语义。Not just document retrieval: create business meaning that can be queried, validated and delivered to agents.

01 · EVIDENCE

多模态业务材料Business evidence

文档、SOP、工单、视频、代码与样例数据；保留来源、版本和适用范围。Documents, SOPs, tickets, video, code and sample data with sources, versions and scope.

业务人员用熟悉的材料共建Co-build with familiar materials

02 · SEMANTICS

业务可读的本体Business-readable ontology

对象与实例、关系、规则、状态、例外和 Action；关联真实数据与证据链。Objects, instances, links, rules, states, exceptions and actions bound to data and evidence.

不是仅供技术人员看的图谱More than a technical graph

03 · VALIDATION

问题与样本验证Question-based validation

用 CQ 题树定义要回答什么；结合题库、Recall Profile、Issue 与专家反馈迭代。Define competency questions; iterate with test banks, Recall Profiles, issues and expert feedback.

依据可追溯，缺口可定位Trace evidence and locate gaps

业务目标 →Goal →目标问题、角色与上下文Questions, roles and context

建模与构建 →Model & build →顶层设计、来源扫描与提案Top level, source scan, proposals

验证与审核 →Validate & review →样本、例外与版本检查Samples, exceptions, versions

交付与更新Deliver & evolveSkill / MCP / A2A、受限令牌Skill / MCP / A2A, scoped tokens

客户可从小范围开始：一组服务 SOP 或典型工单先形成规则与小本体；业务更新进入审核、验证和发布，不必先建全企业大型本体。Start small: model a service SOP or ticket set first; review, test and release changes instead of building a company-wide ontology upfront.
